# Медиа для README

Сюда кладутся картинки и видео. Что чем снимать:

| файл | что на нём | чем снять |
|---|---|---|
| `brain.png` | мозг по нейропилям | уже собран: `python tools/build_cloud.py`, затем офлайн-рендер |
| `stage.png` | сцена «муха работает в 1С» | `python tools/screenshot.py stage` |
| `lab.png` | лаборатория коннектома | `python tools/screenshot.py lab` |
| `fly.png` | муха в студийном свете | `python tools/screenshot.py cinema` |
| `home.png` | стартовая страница | `python tools/screenshot.py home` |
| `timelapse.mp4` | таймлапс работы мухи | см. ниже |
| `timelapse.gif` | он же для README | собирается из mp4, см. ниже |

Важно: сцена перед съёмкой должна быть пересобрана — `python run_lab.py stage`.
Она заново учит муху и записывает настоящий прогон, поэтому числа на кадрах меняются
от сборки к сборке. Это не баг: у политики много ходов с равной оценкой, и ничьи
каждый раз ложатся по-своему.

`python tools/screenshot.py` без аргументов снимет всё подряд. Инструмент открывает
страницу в отдельном окне Edge, ждёт отрисовки и снимает именно это окно. Рабочий стол
должен быть свободен: если поверх висит полноэкранная игра или видео, окно браузера
не выйдет на передний план, и снимок не будет сделан — это защита от того, чтобы
случайно не заснять чужой экран. Ручной запасной вариант: кнопка «кадр в PNG»
на странице или Win+Shift+S.

## Как снять таймлапс

```bat
python tools/record.py                  REM 10_ms_lab1, ×4, 20 секунд -> docs/timelapse.mp4
python tools/record.py 20_ds_lab1 26   REM другая лаба и другая длительность
```

Инструмент собирает отдельную копию сцены, где лаба уже выбрана, но прогон стартует
не сразу: 16 секунд уходит на загрузку страницы и вывод окна вперёд, иначе при ×4 муха
успевает всё закрыть до первого кадра. Дальше окно снимается через ffmpeg (gdigrab)
строго по своему прямоугольнику. Проверка та же, что у скриншотов: если окно не вышло
на передний план, запись отменяется, чтобы в кадр не попал чужой экран.

Во время записи не трогай мышь и не переключай окна — захват идёт с экрана.
Нужен `ffmpeg` в PATH. Хвост ролика подрезается длительностью: прогон одной лабы при ×4
занимает около 18 секунд, поэтому 20 — это ровно до финального «проверок 16/16».

Руками то же самое: открыть `report/stage.html`, выбрать лабу и скорость ×4, снять окно
через Win+G или OBS.

### GIF для README

GitHub **не проигрывает** mp4, на который сослались путём из репозитория: файл лежит,
но на странице видна только ссылка. Поэтому в README вставлен GIF — его GitHub
показывает и крутит сам. Собирается из готового mp4 в два прохода (палитра, потом
кадры), иначе получается грязь и лишние мегабайты:

```bat
ffmpeg -y -i docs/timelapse.mp4 -vf "fps=9,scale=680:-1:flags=lanczos,palettegen=max_colors=128" pal.png
ffmpeg -y -i docs/timelapse.mp4 -i pal.png -lavfi "fps=9,scale=680:-1:flags=lanczos[x];[x][1:v]paletteuse=dither=bayer:bayer_scale=3" -loop 0 docs/timelapse.gif
```

Выходит около 3 МБ при 680 пикселях и 9 кадрах в секунду — текст в окне 1С ещё читается.
Если нужен ролик со звуком и в полном качестве прямо на странице GitHub, его надо
загрузить через веб-интерфейс: перетащить mp4 в описание release или в issue, GitHub
выдаст ссылку вида `user-attachments/assets/...`, и вот она уже проигрывается.

## Как проверить, что муха жмёт нужную клавишу

Открыть `report/stage.html`, консоль браузера:

```js
FlyRig.probe('с')        // куда пришёлся удар по этому символу
FlyRig.keyFor(':')       // {rus:"6"} — двоеточие это Shift+6 на ЙЦУКЕН
```

`dxy` в ответе — промах кончика лапки мимо центра клавиши в единицах сцены (шаг клавиш
0,16). Ноль означает попадание в центр. `pressed` — на сколько клавиша утоплена.

Для ролика «муха в студии» — `report/cinema.html`: слева она думает, поправляет
очки и печатает по кругу, справа вращается мозг.
